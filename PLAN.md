### Эталон: дефекты, которые хороший прогон должен найти в выданном документе
(используем только для оценки качества, **не для хардкода**)
- Ф-2 «по дате совершения покупки» ↔ критерий приёмки №2 (покупка 31.01, засчитана в февраль).
- Ф-3 «максимум один push за месяц» ↔ Ф-4 «push независимо от истории».
- Ф-3 не связан с переключателем «включено/выключено».
- Ф-4: что делать, если накопленная сумма уже ≥ нового порога.
- Возврат после отправленного push: повторное пересечение порога.
- «Проведённые покупки»: авторизация или клиринг.
- НФТ «в течение минуты»: нет точки отсчёта, перцентиля и способа измерения; цель «в момент покупки».
- Данные: сумма покупки в тиынах, а порог в тенге; нет `enabled`, даты покупки, связи возврата.
- Идемпотентность: «сохраняет исходный итог» без ключа дедупликации.
- UI показывает «сумму за месяц», но в API нет метода её чтения; нет чтения настроек вообще.
- Текст ошибки ввода в UI не определён.
- Часть B: `GET` для сохранения; описание «сохранение» и «чтение» одновременно; нет Prod URL и Swagger.
- 200 «Created» с `result: ERROR` при наличии 400; 201 упомянут, но не описан.
- В разделе 403 сказано, что возвращается 404; 404 нет в списке статусов.
- `amount`/`enabled` integer в запросе, string в ответе; `Content-Type: application/json` при «тело не используется».
- Шаг 5 логики «вернуть прежнее состояние», но в примере ERROR состояния нет.
- Названия сервисов не совпадают: «сервис настроек»/AlertsController, «учёт расходов»/«сервис расходов».
- Push передаёт последние 4 цифры карты: содержимое push не описано в ФТ.
- Раздел тестирования пуст; критерии приёмки не покрывают возврат, смену порога, границы, выключенное уведомление, дубль события.
- Версия/дата документа не заполнены, чек-лист ревью без отметок, согласующие пусты.
