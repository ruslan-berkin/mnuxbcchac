ЗАДАЧА: СЕГМЕНТАЦИЯ. Выдели из документа отдельные требования, у которых НЕТ явного номера (в запросе перечислены уже найденные требования с номерами, их не повторяй).

Что считать требованием: любое утверждение, которое задаёт, как должна вести себя система, или ограничение на неё. Это функциональные и нефункциональные требования, требования к данным, интеграции, интерфейсу (UI), правила и логика работы API (шаги логики, особые правила, параметры запроса и ответа, статусы ответов), критерии приёмки (каждая строка таблицы приёмки — отдельное требование).

Что НЕ считать требованием: заголовки, служебные поля (автор, ссылка на задачу, название проекта), описание контекста без обязательств, чек-листы ревью, блок согласующих, примеры кода сами по себе, пустые разделы.

Правила:
- quote — дословная цитата из документа (одно предложение, один пункт списка или одна строка таблицы). Не склеивай разные места.
- summary — краткая формулировка по-русски, не длиннее 160 символов.
- kind: functional | nonfunctional | data | integration | acceptance | api | ui | other.
- source_id: номер, если он явно записан в документе у этого требования; иначе null.
- Одно требование — одна запись. Если пункт содержит несколько независимых обязанностей, всё равно верни одну запись с цитатой пункта.
- Не пропускай требования из таблиц и из разделов про API.

Верни JSON: {"requirements": [{"source_id": ..., "kind": ..., "quote": ..., "summary": ...}]}
