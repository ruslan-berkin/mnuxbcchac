ЗАДАЧА: ПРОВЕРКА ОТДЕЛЬНЫХ ТРЕБОВАНИЙ. Проверь каждое требование из списка по критериям (29148 п. 5.2.5, IEEE 830 п. 4.3). Используй только эти коды:

<<criteria>>

Как проверять:
- Читай требование вместе с контекстом раздела, но замечания делай к самому требованию. Для каждого замечания в requirement_ids укажи ID требований из списка (R-xx), к которым оно относится.
- Однозначность (UNA): ищи оценочные слова, неопределённые ссылки, открытые перечни, не заданные единицу, границу, точку отсчёта, перцентиль, способ измерения.
- Полнота (CMP): можно ли реализовать без догадок? Заданы ли условия, значения, исключения, поведение на границах и при ошибках? Что происходит с уже накопленным состоянием при изменении настроек?
- Проверяемость (VER): можно ли написать тест с ответом «выполнено / не выполнено»? Есть ли измеримый критерий?
- Единичность (SNG): нет ли в одном требовании нескольких независимых обязанностей, склеенных союзами.
- Уместность (APP): нет ли навязанного решения (технология, структура данных) там, где нужна потребность.
- Выполнимость (FEA), корректность (COR), необходимость (NEC), соответствие шаблону (CNF) — только если есть конкретная причина.
- Не проверяй согласованность между разными требованиями: это делается отдельным шагом. Но если дефект виден внутри самого требования или в его критерии приёмки из контекста, укажи его.

Перед ответом по каждому требованию задай себе: «Какой конкретный тест или строку кода нельзя написать из-за этого дефекта?» Если ответа нет, замечание не нужно.

Верни JSON: {"findings": [{"requirement_ids": ["R-01"], "criterion": "UNA", "severity": "major", "quotes": ["..."], "problem": "...", "fix": "...", "question": "..."}]}. Если замечаний нет, верни {"findings": []}.
